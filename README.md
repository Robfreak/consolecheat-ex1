# Title-ID-Finder

Standalone search for PlayStation 4 and PlayStation 5 title IDs, built to sit next to [consolecheat.com](https://consolecheat.com). German is the primary language. The same language list, light/dark theme, and warm card layout as the hub are included so the page can later move in as its own card.

No account, no tracking, nothing uploaded. A search stays in the browser tab. Language and theme are the only things kept locally, same as the hub.

Expected site: <https://robfreak.github.io/consolecheat-ex1/>

## What it does

- Search by game name. Typos and partial names work (`god of wr`, `gran turismo`, `the last of us`).
- Search the other way: paste `CUSA07820`, `PPSA01317`, or a full content ID such as `EP9000-CUSA07410_00-…`.
- One game can have many IDs. Each row is one ID, labeled with platform (PS4 / PS5) and region (EU, US, JP, Asia, KR, INT).
- Tap an ID to copy it. That is the hand-off for the later PS4 Saves tool.

Region comes from the content-ID territory prefix in the source data (first letter: E Europe, U Americas, J Japan, H Asia, K Korea). A second tag such as UK is shown only when the entitlement label in that same record ends in a known code. IDs whose row has no region stay labeled unknown. No ID in the index was invented.

## Data

Generated by `scripts/build-titles.mjs` from the MIT-licensed list [andshrew/PlayStation-Titles](https://github.com/andshrew/PlayStation-Titles) (`All_Titles.tsv`). The compact file is `public/titles.json`. See `THIRD_PARTY_NOTICES.md`.

```bash
npm run data    # refresh public/titles.json
npm test        # fuzzy search and the checks below
npm run build   # refresh, typecheck, Vite build (base /consolecheat-ex1/)
```

## GitHub Pages

`.github/workflows/pages.yml` builds on every push to `main` and pushes `dist/` to the orphan branch `gh-pages` (`peaceiris/actions-gh-pages`, Jekyll off).

Vite `base` is `/consolecheat-ex1/`, which matches a project site at `https://robfreak.github.io/consolecheat-ex1/`.

The Actions token can update `gh-pages` only when Actions has write permission. It often cannot turn Pages on. If the URL is not live, the repo owner does this once:

1. **Settings → Actions → General → Workflow permissions → Read and write permissions.** Save.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch.**
3. **Branch: `gh-pages`, folder: `/ (root)`.** Save.

After that, the site is served from the branch the workflow already fills. The first deploy can take a minute.
